decode MoE kernel：padding 白算，以及交错改造

对应分享文档 4.1 节（kernel p2_fused11n → p2_fused11o / 11p，仍是 BF16）。动画是示意，时间单位按比例缩小，真实数字见文末。

1. 背景：kernel 怎么遍历专家

按专家并集遍历 一个 decode step 有 T 个 token，每个 token 选 top-8 专家。kernel 先求这 T 个 token 选中专家的并集，再把并集按 slot 奇偶分给 2 个物理核。每个核依次处理自己的 slot：先把该专家的权重 DMA 进来，再做 matmul / 激活 / 加权求和。
循环是静态展开的 并集里有多少个专家要到运行时才知道（取决于路由），但 NKI 循环要在编译期展开，所以每核固定展开 NSL = min(64, 4T) 个位置。实际只有 n 个是真实专家，多出来的 NSL − n 个就是 padding。T=16 时 NSL=64，每核真实 slot 约 41 个。 
# 示意（每个物理核）
for j in static_range(NSL):            # NSL = min(64, 4T)，编译期常量
    e = slot_expert[j]                 # j ≥ n 时是越界 id
    dma(weights[e] → ring_buf[j % R])  # 越界 → DMA 被跳过（oob skip）
    matmul / act / dve(ring_buf[j % R])# 照样执行；affinity 为 0，结果不影响输出

decode 受 HBM 带宽限制：真实 slot 的计算要等权重 DMA 到位，PE 在两次 DMA 之间本来就有空档。问题出在 padding 位置排在哪里。

3. 改造做了什么

改造前（11n）改造后（11o / 11p）
处理顺序slot 0, 1, 2, …, NSL−1 按自然顺序；padding 一定是最后那一批前 R 个 slot 不动（ring buffer 预热，语义不变），其余 slot 按位反转顺序处理，把 padding 打散到真实 slot 之间
padding 的计算最后一次 DMA 结束后，padding 的 matmul / ACT / DVE 排成一条串行尾巴，没有 DMA 可以重叠落在两次 DMA 之间的空档里，被 DMA 时间盖住
索引方式step = slotring buffer 和 DMA 提前量按处理 step 编号；专家 id 和 affinity 列按 slot 编号
T 的上限16（T=32 要调两次）11p 支持 T≤32：T>16 时 down 投影累加到 2 个 64 行的 PE tile
数值不变：padding 的 affinity 仍是 0，只是换了计算顺序；GSM8K 0.934 → 0.934
